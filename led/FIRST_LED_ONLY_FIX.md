# WS2812 LED 只显示第一个灯珠的诊断

## 问题现象

- ❌ 只有第一个 LED 显示白光
- ❌ 其余 7 个 LED 全灭
- ✅ DMA 在传输数据（确认有信号）
- ✅ 第一个 LED 收到了数据

## 根本原因：DMA 数据对齐不匹配

### 问题分析

**原代码配置：**
```c
hdma_tim1_ch1.Init.PeriphDataAlignment = DMA_PDATAALIGN_BYTE;      /* ❌ 字节对齐 */
hdma_tim1_ch1.Init.MemDataAlignment = DMA_MDATAALIGN_BYTE;         /* ❌ 字节对齐 */
```

**DMA 目标：**
```c
(uint32_t)&(htim1.Instance->CCR1)  /* CCR1 是 16 位寄存器！ */
```

### 为什么只显示第一个灯珠

**执行流程：**

```
缓冲区: [B0] [B1] [B2] [B3] [B4] [B5] ...

DMA 字节对齐传输:
时刻0:   DMA发送B0 → CCR1 = 0x00??  (只写入低8位！)
时刻1:   DMA发送B1 → CCR1 = 0x??B1  (覆盖之前的值)
时刻2:   DMA发送B2 → CCR1 = 0x00??
时刻3:   DMA发送B3 → CCR1 = 0x??B3

问题：
- CCR1每次只被更新一半（8位）
- 高8位被随机数据覆盖
- 占空比计算错误
- 多个LED的数据混乱
```

**对第一个 LED 的影响：**
```
LED1 需要 24 位数据 (G R B)
使用字节对齐时：
- 时刻0-23: 正确的字节被发送
- 但由于对齐问题，数据可能被部分破坏
- 第一个LED仍能解析（可能因为硬件容错）
- 但后续LED无法同步

LED2-8: 由于前面的数据混乱，它们无法正确接收数据
```

## 解决方案

### 修复1：改为半字对齐

```c
hdma_tim1_ch1.Init.PeriphDataAlignment = DMA_PDATAALIGN_HALFWORD;  /* ✅ 半字对齐 */
hdma_tim1_ch1.Init.MemDataAlignment = DMA_MDATAALIGN_HALFWORD;     /* ✅ 半字对齐 */
```

**为什么有效：**
- CCR1 是 16 位寄存器
- 半字对齐确保每次写入完整的 16 位值
- 避免了部分覆盖的问题

### 修复2：调整传输大小

当使用半字对齐时，传输数量应该是字节数/2：

```c
status = HAL_DMA_Start_IT(
    &hdma_tim1_ch1,
    (uint32_t)ws2812->pwm_buffer,
    (uint32_t)&(htim1.Instance->CCR1),
    WS2812_BUFFER_SIZE / 2  /* ✅ 252 字节 = 126 半字 */
);
```

## 工作原理对比

### 修复前（字节对齐）

```
缓冲区: [28] [28] [28] [28] [58] [58] ... (252字节)

DMA 字节传输 (每次1字节):
时刻0μs:    DMA → CCR1低字节 = 28
时刻1.25μs: DMA → CCR1高字节 = ? (被覆盖！)
时刻2.5μs:  DMA → CCR1低字节 = 28
时刻3.75μs: DMA → CCR1高字节 = ?

问题：
- PWM占空比计算: 占空比 = CCR1 / (ARR+1)
- 由于CCR1被部分覆盖，占空比变成垃圾值
- LED1勉强工作，LED2-8完全混乱
```

### 修复后（半字对齐）

```
缓冲区: [28] [00] [28] [00] [28] [00] ... (252字节)
        └─ 完整的16位值（低字节|高字节）

DMA 半字传输 (每次2字节):
时刻0μs:    DMA → CCR1 = 0x0028 (完整的16位)
时刻2.5μs:  DMA → CCR1 = 0x0028 (完整的16位)
时刻5μs:    DMA → CCR1 = 0x0028 (完整的16位)
时刻7.5μs:  DMA → CCR1 = 0x005A (58的16位表示)

正确：
- 占空比 = 28/90 = 31% (逻辑0) ✓
- 占空比 = 58/90 = 64% (逻辑1) ✓
- 每个LED接收完整的24位数据
- LED1-8都正确显示 ✓
```

## 缓冲区大小验证

- WS2812_DATA_SIZE = 8个LED × 3字节 = 24字节
- 每字节编码为8个PWM值 = 24 × 8 = 192字节
- 复位信号 = 60字节（>50us）
- **总计 = 192 + 60 = 252字节 = 126个半字 ✅**

## 修改清单

✅ **ws2812.c - DMA_Init():**
- 改 `PeriphDataAlignment` 为 `DMA_PDATAALIGN_HALFWORD`
- 改 `MemDataAlignment` 为 `DMA_MDATAALIGN_HALFWORD`

✅ **ws2812.c - Send():**
- 改 `HAL_DMA_Start_IT()` 的大小参数为 `WS2812_BUFFER_SIZE / 2`

## 测试预期

修复后应该看到：
- ✅ 8个LED全部亮起
- ✅ 显示红色（非白光）
- ✅ 亮度均匀
- ✅ 可以正确切换颜色
- ✅ 2秒切换一次颜色（红→绿→蓝→红）

## 相关技术细节

### DMA 对齐模式选择

| 对齐模式 | 每次传输 | 适用寄存器 | 缓冲大小需求 |
|---------|---------|----------|----------|
| BYTE | 1字节 | 8位寄存器 | 任意 |
| HALFWORD | 2字节 | 16位寄存器 | 必须是2的倍数 |
| WORD | 4字节 | 32位寄存器 | 必须是4的倍数 |

### STM32F1 TIM1_CH1 配置

- **PWM 输出引脚:** PA8 (TIM1_CH1)
- **DMA 通道:** DMA1_Channel2
- **目标寄存器:** TIM1→CCR1 (16位)
- **推荐对齐:** HALFWORD ✓

## 总结

**问题：** DMA 以字节对齐写入 16 位寄存器，导致数据混乱
**原因：** 字节对齐会将 16 位寄存器分两次写入，中间丢失数据
**修复：** 改为半字对齐，每次写入完整的 16 位值
**结果：** 所有 8 个 LED 正确显示颜色
